# Μηνύματα: σειρά SQL

Δεν τρέχει μόνο του. Μετά το deploy του PR, στον Supabase SQL Editor:

1. `01_rls_and_summary_index.sql` — υποχρεωτικό. Κλείνει τις συνομιλίες ώστε κάθε χρήστης να βλέπει μόνο τις δικές του, και προσθέτει το index για τη σύνοψη email.
2. `02_schedule_summary_cron.sql` — προαιρετικό αν το υπάρχον pg_cron του `check-inactive-conversations` τρέχει ήδη κάθε λίγα λεπτά (αυτό το cron στέλνει και τις συνόψεις). Αλλιώς τρέξτε το, αφού αντικαταστήσετε το `YOUR_CRON_SECRET`.

Rollback: `99_rollback.sql` (δεν σβήνει μηνύματα ούτε τη στήλη `email_sent`).

Η σύνοψη στέλνεται το πολύ μία φορά ανά παραλήπτη, για μηνύματα που είναι ακόμα αδιάβαστα, αφού η συνομιλία μείνει ήσυχη `MESSAGE_SUMMARY_QUIET_MINUTES` λεπτά (προεπιλογή 20, όρια 5–180). Ρυθμίστε το στο Vercel αν θέλετε άλλο παράθυρο. Το ρητό «Τέλος συνομιλίας» στέλνει τη σύνοψη αμέσως, μόνο για αυτή τη συνομιλία.

Αν η στήλη `email_sent` δεν υπήρχε, τα παλιά αδιάβαστα μηνύματα θα πάρουν και αυτά μία σύνοψη (25 συνομιλίες ανά τρέξιμο). Αν δεν το θέλετε, πριν το πρώτο cron τρέξτε: `UPDATE public.messages SET email_sent = true WHERE created_at < now();` Τα καινούρια μηνύματα γράφονται με `email_sent = false`.

Δεν υπάρχει σελίδα ρυθμίσεων email, οπότε το μήνυμα δεν έχει σύνδεσμο διαγραφής από λίστα.
